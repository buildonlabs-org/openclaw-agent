# OpenClaw Agent Custom Instructions

## Cron Job Creation & Result Delivery

When creating or updating OpenClaw cron jobs, you must POST the full results to the webhook yourself to enable frontend notifications.

### Critical: How to Deliver Results

**DO NOT use webhook delivery mode** - it only sends summaries, not full responses.

Instead:
1. Set delivery mode to `"none"`
2. After completing your work, POST the full result to: `{{AGENT_URL}}/api/openclaw-cron-webhook`

### Required Implementation Pattern

When the user asks to create a cron job:

1. **Execute the cron job creation** with `--delivery none`:
```bash
openclaw cron add \
  --name "Your Job Name" \
  --cron "* * * * *" \
  --message "Your task instructions. CRITICAL: After completing your work, POST the FULL result to {{AGENT_URL}}/api/openclaw-cron-webhook as JSON: {jobName: 'Your Job Name', status: 'success', content: 'your complete response', timestamp: 'ISO timestamp'}. Use curl, fetch, or any HTTP tool available." \
  --delivery none
```

2. **The message must include instructions** for the agent to POST results, because OpenClaw's webhook delivery mode only sends summaries.

### Example Commands

**User asks:** "Monitor $HYPE price every minute"

**You execute:**
```bash
openclaw cron add \
  --name "Monitor $HYPE Price" \
  --cron "* * * * *" \
  --message "Get current $HYPE price. CRITICAL: After getting the price, POST the full result to {{AGENT_URL}}/api/openclaw-cron-webhook as JSON: {jobName: 'Monitor $HYPE Price', status: 'success', content: 'your price data here', timestamp: 'ISO timestamp'}." \
  --delivery none
```

**User asks:** "Remind me to check positions at 9am daily"

**You execute:**
```bash
openclaw cron add \
  --name "Daily Position Check" \
  --cron "0 9 * * *" \
  --message "Review current positions. CRITICAL: After reviewing, POST the full results to {{AGENT_URL}}/api/openclaw-cron-webhook as JSON: {jobName: 'Daily Position Check', status: 'success', content: 'your position review here', timestamp: 'ISO timestamp'}." \
  --delivery none
```

### Why This Approach?

- ❌ **delivery.mode = "webhook"** → Only sends summary snippets like "✅ Completed successfully"
- ✅ **delivery.mode = "none" + agent POSTs** → Sends your complete, full response with all data

This ensures the launcher UI receives complete responses, not just summaries.

### Webhook Payload Format

When POSTing to the webhook, use:
```json
{
  "jobName": "Your Job Name",
  "status": "success",
  "content": "Your complete response text with all data",
  "timestamp": "2026-03-15T10:30:00Z"
}
```

## Telegram-Aware Cron Job Creation

When a user asks for a cron job **from a Telegram conversation**, you MUST configure explicit Telegram delivery so results are sent directly back to their Telegram chat.

### How to Get the User's Telegram Chat ID

The Telegram chat ID is required to deliver cron results back to the correct user. To get it:

1. Run: `openclaw pairing list --channel telegram` — this shows paired Telegram accounts and their chat IDs.
2. If the user's Telegram is not listed, ask them to send you a message via Telegram first, then run the pairing list command again.
3. You can also ask the user directly: "What is your Telegram chat ID? You can find it by messaging @userinfobot on Telegram."

### Telegram Cron Job Pattern

When creating a cron job for a Telegram user, use `--channel telegram --to <TELEGRAM_CHAT_ID>`:

```bash
openclaw cron add \
  --name "XRP Price Every Minute" \
  --cron "* * * * *" \
  --message "Get the current price of $XRP and report it clearly." \
  --channel telegram \
  --to <TELEGRAM_CHAT_ID>
```

This ensures OpenClaw delivers the cron run result directly to the user's Telegram chat, not just to the launcher UI.

### Confirming Telegram Delivery Setup

After creating the cron job with Telegram delivery, confirm to the user:
- ✅ The cron job was created with Telegram delivery configured
- ✅ Results will be sent to their Telegram chat (chat ID: `<TELEGRAM_CHAT_ID>`)
- ✅ The first delivery will happen at the next scheduled run

If you cannot determine the Telegram chat ID, tell the user:
> "I've created the cron job, but I need your Telegram chat ID to deliver results directly to you in Telegram. Please message @userinfobot on Telegram to get your chat ID, then tell me and I'll update the cron job."

### Combined Telegram + Webhook Pattern (when also notifying the frontend)

If both frontend notifications and Telegram delivery are needed:

```bash
openclaw cron add \
  --name "XRP Price Every Minute" \
  --cron "* * * * *" \
  --message "Get the current price of $XRP. CRITICAL: After getting the price, POST the full result to {{AGENT_URL}}/api/openclaw-cron-webhook as JSON: {jobName: 'XRP Price Every Minute', status: 'success', content: 'your price data here', timestamp: 'ISO timestamp', telegramChatId: '<TELEGRAM_CHAT_ID>'}." \
  --channel telegram \
  --to <TELEGRAM_CHAT_ID>
```

## Default Behavior

Unless the user explicitly requests NO notifications, always:
1. Use `--delivery none`
2. Include instructions in the message for the agent to POST full results to the webhook

For Telegram users specifically, ALSO add `--channel telegram --to <TELEGRAM_CHAT_ID>` to ensure direct Telegram delivery.
